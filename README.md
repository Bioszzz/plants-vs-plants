# 植物斗争

一个植物对战卡牌游戏，纯 Python 标准库实现，**零第三方依赖**。

这个包是**最小可运行集合**：只有跑起来需要的代码、网页资源和启动脚本。
规则文档、开发笔记不随包发布。

- 需要 **Python 3.9 或更高**（纯标准库，不需要装任何东西，也不需要 tkinter）
- 不需要 `pip install` 任何东西

---

## 一、双击就能玩（推荐）

五个 `.bat` 都会自己找 Python，不用配 PATH。

| 脚本 | 干什么 |
|---|---|
| `网页版.bat` | **浏览器客户端**。填房主的地址就能加入对局；连接前可以勾「玩家选项」（自动录像 / 服务器友好）。<br>同机练习和电脑打请用 `多开试玩台.bat`。 |
| `房主控制台.bat` | **只观战的房主**。开一局等你连，自己在控制台页面看战报和场面，不下场。把本机 IP 告诉玩家即可。 |
| `多开试玩台.bat` | **一台机器开多个真人座位**。在配置页上设人数 / 电脑数 / 开局种子 / 规则集 / 每个座位的名字，点「一键开局」会弹出 N 个浏览器标签，每个标签是一个独立玩家 —— **想同屏双人对打就用它**（人数填 2、电脑填 0）。 |
| `图鉴.bat` | **植物图鉴**。独立页面，不用开局、不用连服务器，38 株植物的数值 / 机制 / 风味文案 / 档案都能翻，按编号或名称搜。 |
| `检查更新.bat` | **检查并自动安装最新版**。查到新版会问一句，回车就开始下载、校验、备份、覆盖。 |

端口：网页客户端 8000 起、房主控制台 8090 起、试玩台配置页 8300 起、图鉴 8400 起，被占用会自动往后找。

> **非 Windows（Linux / Android Termux）**：`.bat` 一个都跑不了 —— 那是 cmd.exe 的脚本语言。
> 试玩台、图鉴和检查更新各有一个等价脚本：
>
> ```sh
> sh 多开试玩台.sh     # = python playtest.py
> sh 图鉴.sh           # = python codex_server.py
> sh 检查更新.sh       # = python updater.py
> ```
>
> 网页版与房主控制台没有对应 `.sh`，直接 `python webui.py` / `python netserver.py`。
> ⚠️ 试玩台只监听 `127.0.0.1`，所以手机上必须**跑在手机自己身上**；跨设备联机走 `netserver.py`。

<details><summary>手机上（Android + Termux）—— 作者自己用过</summary>

- 装好 Termux，把整个文件夹放进去（或 `git clone` 下来），再 `cd` 进那个目录。
- 上面那三个 `.sh` 直接 `sh 文件名` 就能跑，**不用记 `python xxx.py`**。
- ⚠️ **切到后台会被系统限流**：安卓会把长时间待在后台的进程降速，网页经常就起不来
  （表现是浏览器一直转圈、或者连接被拒）。作者的解法是**分屏** —— 让 Termux
  留在前台，另一半屏幕开浏览器。
- 作者的用法是**在手机上本地玩 / 测试**（试玩台、翻图鉴），**没有在手机上开过服务端**。
  换一部手机、换一个安卓版本，情况可能不一样。

</details>

## 二、手动运行

```bash
python main.py                      # 控制台热座（最简）
python webui.py                     # 浏览器客户端
python netserver.py 2 1 8080 7      # 开服：2 人、1 个电脑、端口 8080、开局种子 7
python netclient.py                 # 终端客户端
python playtest.py                  # 多开试玩台（配置页 + N 个座位）
python codex_server.py              # 植物图鉴（独立页面，跟对局无关）
python updater.py                   # 检查并更新到最新版（--check 只查不装）
```

`netserver.py` 参数：`[人数] [电脑数] [端口] [开局种子]`

- 不带 `--keep`：打完一局服务端就退出
- 带 `--keep`：打完一局**不退出**，玩家点「再来一局」重连同一端口就是下一局
- `--open`：开服并自动打开房主控制台页面

## 三、联机怎么玩

作者联机用 **RadminVPN**：先让所有人进同一个虚拟局域网，再开局。

1. 所有人都装好 RadminVPN，加入同一个网络。**跨网时这一步不做，后面一定连不上。**
2. 房主双击 `房主控制台.bat`（或运行 `python netserver.py 2 0`），在页面里点「开局」。
3. 房主把**两样东西**发给玩家：
   - **Radmin 客户端上显示的那个地址**
   - 页面上的「游戏端口」（默认 `8091`）
4. 玩家双击 `网页版.bat`，在「服务器 IP」里填 `地址:端口`，点连接。
5. 人齐了自动开局。

**端口是这里最常见的错**：只填地址不填端口时，程序会按 `8080` 去连；而「房主控制台」
默认的游戏端口是 **8091**（跟着控制台端口 8090 往后一位，被占用会再往后找）。
所以第 3 步那个数是必须的，不是可选的。

同机测试更省事：直接双击 `多开试玩台.bat`，不用装 Radmin。

<details><summary>房主有公网地址的情况（可以不走 Radmin）</summary>

少数家宽有真正的公网 IP，或者自己做过端口映射 —— 那种情况直接把公网地址发给玩家就行。

判断有没有：`ipconfig` 里如果只有 `192.168.x.x`、`10.x.x.x`、`100.x.x.x` 这类地址，
说明你没有公网 IPv4，只能走 Radmin 这类方案。校园网基本都是这样。

</details>

> ⚠️ RadminVPN 是第三方工具，**本项目不提供支持、也不分发安装包**，请从官网下载。
> ⚠️ 上面这套是**作者自己试过的**（校园网环境），换个网络环境可能不一样。
> 不灵就换别的同类工具，原理一样：先组虚拟局域网，再按上面步骤连。

### 连接卡片上的两个勾选框（玩家选项）

| 选项 | 干什么 | 什么时候勾 |
|---|---|---|
| **自动录像** | 把这一局另存一份到你的 `对局录像/`（文件名 `客户端_*.json`） | 想留档 / 复盘 / 报 bug 时 |
| **服务器友好** | 服务器**不再发战报文字**，改成把「操作序列」发给你，战报在你自己的机器上算 | 房主带宽紧、人比较多的时候 |

两个都只影响你自己：勾了不改变任何规则，也不会让别人多做什么。勾完直接点「连接服务器」就行
（没连上时勾的也会记住，连上那一刻补报）。

**为什么会有「服务器友好」**：一局的中文战报大约 50~300 KB，而同样的信息用
「谁在哪一步选了什么」表示只要 2~5 KB。服务器是**按人**分流发送的，所以
哪怕房间里只有你一个人勾了，你那一份也照样省下来。

> ⚠️ 前提是你和房主跑的是**同一份 `engine.py`**。自己改过代码的话，
> 你算出来的战报会跟服务端不一样 —— 那只影响你自己看到的东西，不影响判定
> （判定在服务端算）。

## 四、文件说明

| 文件 | 作用 |

| `main.py` | 控制台热座入口 |
| `engine.py` | 规则引擎（回合流程、结算顺序、胜负） |
| `plants_data.py` | 所有植物的数值与规则字段 |
| `webui.py` / `netserver.py` | 网页客户端 / 联机服务端 |

| `playtest.py` | 多开试玩台 |

| `codex_server.py` | 植物图鉴的**独立服务**（独立进程、独立端口 8400，跟对局无关） |
| `codex_text.py` | 图鉴的"说法"：每株的风味与档案。**数值不在这里**，一律现读 `plants_data` |
| `updater.py` | 自动更新器（网页里的「立即更新」和 `检查更新.bat` 都走它） |

| `names.json` | 你上次用的名字，自动生成，可以删 |
| `_backup/` | 更新前自动备份的旧文件，确认新版没问题后可以删 |

| 文档 | 讲什么 |

## 五、录像、回退、自动保存

每局都会自动录一份，存在项目里的 **`对局录像/`** 文件夹（不是浏览器的下载目录）：

| 文件 | 什么时候写的 |
|---|---|
| `进行中.json` | 每回合覆盖写一次 —— 中途崩了也只丢最后半回合 |
| `20261115_214803_4人局.json` | 一局结束时（同时把上面那个删掉） |
| `示例-4人局.json` | 附带的样例，拿它试功能用 |

录像存的是"谁在哪一步答了什么"，不是战报文字，所以很小（一局十几到几十 KB），
但足够把整局**一模一样地重跑一遍**：

```bash
python replay.py              # 重放最新一局（不用记文件名）
python replay.py --list       # 看看有哪些录像
python replay.py 示例          # 名字里带"示例"的那份
python replay.py 示例 --out 战报.txt        # 不刷屏，写进文件
python replay.py 示例 --verify 原战报.txt   # 和原战报逐字比对（改过引擎后校验用）
```

「多开试玩台」的座位页右上角还有两个按钮：

| 按钮 | 作用 |
|---|---|
| **↶ 回退** | 点一下 = 退回**本回合开始**（最常用）。旁边的小 **▾** 才展开「上一回合 / 指定回合（填 0 = 从开局重来）」。战报会清空、从头重播 |
| **⭳ 录像** | 立刻把当前进度存进 `对局录像/` —— 对局中途也能存，重放会停在同一个地方 |

**打完了也能回退**：结算界面出来后按「↶ 回退」照样管用 —— 会把这一局退回你要的那一回合、
各座位自动重连、接着打（那一局也会从「本服战绩」里撤掉，不会重复计数）。

### 想从某一局的中途接着打

「多开试玩台」配置页**最下面**有个折起来的 **「从录像续玩（选填）」**：

1. 展开，选一份录像（选项里写着几人局、到第几回合）—— 人数 / 种子 / 规则会自动跟着录像走。
2. 点「一键开局」。服务端先把录像里的操作**快进**一遍（几秒，战报会刷过去），停在该你操作的地方。
3. 之后照常玩。配合「回退」就是"回到某个决策点重打一遍"。

> 录像只在**你这台机器**上，没上传到任何地方。发给别人，对方也能重放 / 续玩。
> 回退和导出只在「多开试玩台」里有；普通单开这两个按钮不显示。

## 六、怎么更新

两种方式，做的是同一件事：

1. **在网页里**：打开网页版 → 左下角「版次」旁边点「检查更新」→ 有新版会出现
   「立即更新到 vX.Y」→ 点它。
2. **双击 `检查更新.bat`**：终端里会问一句「要更新到 vX.Y 吗？」，回车就开始。

更新器会：查 Gitee 上的公开发行版 → 下载 zip → **校验**（路径不许越界、关键文件
必须齐全、解压后真跑一次 `import`）→ 把要覆盖的旧文件备份到 `_backup/v旧_时间戳/`
→ 逐个覆盖。

- 只覆盖包里那 **33** 个文件，**`names.json` 和你的其它东西一概不碰**。
- 如果文件夹名里带着旧版本号（如 `plant-vs-plant-v0.72`），更新完会**在窗口关掉后**
  自动改成新版本号；你自己起的名字（如「植物斗争」）不会被改。
- **更新完必须关掉程序重新打开** —— 现在跑的仍然是旧代码。
- 万一新版有问题：把 `_backup/` 里那份拷回去就行。
